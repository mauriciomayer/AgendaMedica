- (decision) Backend: Firebase (Firestore + Cloud Functions 2nd gen + Firebase Authentication + Firebase Cloud Messaging). Escolhido apos apresentar troca com API propria+Postgres
- (decision) Mobile: Kotlin + Jetpack Compose nativo (caminho padrao Android), roda em dispositivo real via Android Studio/USB ou APK assinado
- (version) Kotlin 2.4.20; Compose BOM 2026.08.00; Compose Compiler Gradle plugin 2.3.21 (verificado via web em 2026-09-17)

- (decision) Paradigma mobile: MVVM com fluxo de dados unidirecional (Compose + ViewModel + StateFlow), padrao recomendado pelo Google para Compose
- (decision) Limite critico: nenhuma escrita direta do app em Consultas; toda mutacao (agendar/cancelar/reagendar) passa por Cloud Function, que executa em transacao atomica do Firestore. Firestore security rules bloqueiam escrita direta do cliente na colecao de consultas
- (decision) Ambientes: um unico projeto Firebase (sem separacao dev/producao) para o MVP
- (decision) Consulta usa campo de status (confirmada/cancelada), nunca hard-delete - mantem historico para Minhas Consultas e auditoria
- (decision) Slots de horario sao computados sob demanda (agenda semanal do medico + consultas ativas), nunca armazenados como documentos individuais
- (decision) Lembrete de 24h disparado por Cloud Function agendada (scheduled/pub-sub, roda a cada poucos minutos), nunca client-triggered
- (decision) Papel da conta (paciente/medico) e fixo, gravado no servidor (custom claim + doc de perfil) e conferido nas security rules / Cloud Functions - nao e alteravel pelo cliente
- (decision) Distribuicao do app: instalacao direta no dispositivo (Android Studio/USB ou APK assinado), sem publicacao na Play Store no MVP
- (decision) Convencao de nomes: colecoes/campos do Firestore em ingles (patients, doctors, appointments, specialty, insurance, status); valores de enum (especialidade, convenio) permanecem em portugues, iguais ao PRD, pois sao conteudo exibido ao usuario
- (decision) Datas/horarios de Consulta armazenados como Firestore Timestamp (nao string), para permitir comparacao/ordenacao nativa nas regras de 24h/48h
- (decision) Erros de Cloud Functions callable usam codigos padrao do HttpsError (ex.: failed-precondition para conflito de slot/janela de cancelamento, invalid-argument para validacao) - convencao unica de erro entre todas as functions
